# 连接失败排查指南

## ❌ 错误信息

```
curl: (7) Failed to connect to 8.217.122.83 port 1025 after 49 ms: Couldn't connect to server
```

## 🔍 排查步骤

### 步骤1: 检查socat服务是否运行

**在中转服务器上执行：**

```bash
# 检查socat服务状态
sudo systemctl status ssr-relay-socat

# 检查端口监听
netstat -tlnp | grep 1025
# 或
ss -tlnp | grep 1025

# 应该看到：tcp  0  0  0.0.0.0:1025  LISTEN  xxxx/socat
```

**如果没有监听，启动服务：**

```bash
# 启动socat服务
sudo systemctl start ssr-relay-socat
sudo systemctl enable ssr-relay-socat
sudo systemctl status ssr-relay-socat

# 检查日志
sudo journalctl -u ssr-relay-socat -n 50 --no-pager
```

### 步骤2: 检查防火墙

**在中转服务器上执行：**

```bash
# 1. 检查ufw状态
sudo ufw status
# 如果显示 "Firewall not enabled"，说明ufw未启用

# 2. 如果ufw未启用，检查iptables
sudo iptables -L -n | grep 1025

# 3. 如果使用iptables，添加规则
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT

# 4. 保存iptables规则
sudo iptables-save > /etc/iptables/rules.v4
# 或
sudo netfilter-persistent save

# 5. 如果ufw未启用但需要启用（可选）
sudo ufw enable
sudo ufw reload
```

**⚠️ 重要：** 如果防火墙未启用，可能是：
- 使用iptables直接管理
- 云服务器安全组控制
- 防火墙被禁用

**检查iptables规则：**

```bash
# 查看INPUT链规则
sudo iptables -L INPUT -n --line-numbers | grep 1025

# 如果没有规则，添加
sudo iptables -I INPUT 1 -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT 1 -p udp --dport 1025 -j ACCEPT

# 保存规则
sudo iptables-save > /etc/iptables/rules.v4
```

### 步骤3: 检查云服务器安全组规则

**重要：** 确保云服务器（阿里云/腾讯云等）的安全组规则允许1025端口的入站流量。

**检查方法：**
1. 登录云服务器控制台
2. 找到安全组设置
3. 添加入站规则：端口1025，协议TCP/UDP，源0.0.0.0/0

### 步骤4: 检查SSR客户端是否运行

**在中转服务器上执行：**

```bash
# 检查SSR客户端状态
sudo systemctl status ssr-client

# 检查端口监听
netstat -tlnp | grep 1080
# 应该看到：tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/ss-local

# 如果未运行，启动服务
sudo systemctl start ssr-client
sudo systemctl enable ssr-client
```

### 步骤5: 测试本地连接

**在中转服务器上执行：**

```bash
# 测试socat转发是否工作
curl --socks5 127.0.0.1:1025 ifconfig.me

# 如果失败，检查socat日志
sudo journalctl -u ssr-relay-socat -n 50 --no-pager

# 如果连接卡住或超时，检查：
# 1. SSR客户端是否正常运行
sudo systemctl status ssr-client
netstat -tlnp | grep 1080

# 2. SSR客户端配置是否正确
cat /opt/shadowsocksr/client-config.json | grep '"server"'
# 应该是 "server": "103.248.229.223"（不是 "0.0.0.0"）

# 3. 测试SSR客户端是否正常工作
curl --socks5 127.0.0.1:1080 ifconfig.me
# 应该返回原始SSR服务器的出口IP
```

### 步骤6: 测试端口连通性

**在本机上执行：**

```bash
# 测试端口是否开放
telnet 8.217.122.83 1025
# 或
nc -zv 8.217.122.83 1025

# 如果显示 "Connection refused"，说明：
# - 端口被防火墙阻止
# - 或云服务器安全组未开放
# - 或服务未监听在0.0.0.0

# 如果显示 "Connection timed out"，说明：
# - 端口完全被阻止（安全组或防火墙）

# 如果连接卡住（hang）或超时，说明：
# - socat服务可能有问题
# - SSR客户端可能未正常运行
# - socat转发配置可能有问题
```

### 步骤6.5: 连接卡住/超时排查

**如果 `nc -vz` 或 `curl` 连接卡住或超时，检查以下内容：**

```bash
# 在中转服务器上执行

# 1. 检查socat服务状态和日志
sudo systemctl status ssr-relay-socat
sudo journalctl -u ssr-relay-socat -n 50 --no-pager

# 2. 检查SSR客户端服务状态
sudo systemctl status ssr-client
sudo journalctl -u ssr-client -n 50 --no-pager

# 3. 检查端口监听情况
netstat -tlnp | grep -E "1025|1080"
# 应该看到：
# tcp  0  0  0.0.0.0:1025  LISTEN  xxxx/socat
# tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/ssr-local

# 4. 测试本地SSR客户端是否正常
curl --socks5 127.0.0.1:1080 ifconfig.me
# 应该返回原始SSR服务器的出口IP（103.248.229.223）

# 5. 测试本地socat转发是否正常
curl --socks5 127.0.0.1:1025 ifconfig.me
# 应该返回原始SSR服务器的出口IP（103.248.229.223）

# 6. 如果本地测试都正常，但外部连接卡住，检查：
# - 云服务器安全组是否开放1025端口（TCP）
# - 是否有其他防火墙规则阻止
```

### 步骤7: 连接卡住/超时 - 深度排查

**如果本地测试正常，但外部连接卡住或超时：**

```bash
# 在中转服务器上执行

# 1. 检查是否有其他防火墙或安全组规则
# 检查iptables所有链
sudo iptables -L -n -v

# 2. 检查是否有DROP或REJECT规则在ACCEPT之前
sudo iptables -L INPUT -n --line-numbers | head -20

# 3. 测试TCP连接（不使用SOCKS5协议）
# 在中转服务器上启动一个简单的TCP监听测试
timeout 5 nc -l 1026 &
sleep 1
# 然后从本机测试：nc -vz 8.217.122.83 1026
# 如果这个也卡住，说明是网络层面的问题

# 4. 检查socat是否真的在转发
# 使用tcpdump监控1025端口流量
sudo tcpdump -i any -n port 1025 -c 10
# 然后从本机尝试连接，看是否有数据包

# 5. 检查SSR客户端日志（看是否有连接尝试）
sudo journalctl -u ssr-client -f
# 然后从本机尝试连接，看是否有日志输出

# 6. 如果tcpdump显示RST包（连接被重置）
# 说明端口没有监听或服务未运行，或者iptables OUTPUT链阻止了连接
# 检查：
sudo systemctl status ssr-relay-socat
netstat -tlnp | grep 1025
# 如果服务未运行，启动服务：
sudo systemctl start ssr-relay-socat
sudo systemctl status ssr-relay-socat

# 7. 检查iptables OUTPUT链（重要！）
sudo iptables -L OUTPUT -n --line-numbers
# 检查是否有DROP或REJECT规则阻止了连接
sudo iptables -L OUTPUT -n | grep -E "DROP|REJECT"

# 8. 如果OUTPUT链有DROP规则，添加ACCEPT规则
sudo iptables -I OUTPUT -p tcp --sport 1025 -j ACCEPT
sudo iptables -I OUTPUT -p tcp --dport 1025 -j ACCEPT

# 9. 检查iptables NAT表（可能影响连接）
sudo iptables -t nat -L -n --line-numbers

# 10. 如果socat监听但返回RST，可能是socat进程问题
# 尝试重启socat服务
sudo systemctl restart ssr-relay-socat
sudo systemctl status ssr-relay-socat
```

**如果tcpdump没有看到数据包，说明：**
- 云服务器安全组可能未正确配置
- 或者有其他防火墙规则阻止

**如果tcpdump看到数据包，但SSR客户端没有日志，说明：**
- socat转发可能有问题
- 或者SSR客户端无法处理这些连接

**如果tcpdump显示RST包（连接被重置），说明：**
- 端口没有监听或服务未运行
- 或者防火墙规则阻止了连接
- **或者iptables NAT表的REDIRECT规则与socat冲突（常见问题）**

**立即检查：**
```bash
# 1. 检查socat服务状态
sudo systemctl status ssr-relay-socat
netstat -tlnp | grep 1025
# 如果服务未运行，启动服务：
sudo systemctl start ssr-relay-socat

# 2. 检查iptables NAT表REDIRECT规则（重要！）
sudo iptables -t nat -L -n --line-numbers
# 如果看到1025端口被REDIRECT到1080端口，这些规则会与socat冲突
# 删除这些规则：
sudo iptables -t nat -D PREROUTING -p tcp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D PREROUTING -p udp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p udp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
# 保存规则
sudo iptables-save > /etc/iptables/rules.v4
```

### 步骤8: 检查iptables INPUT规则

**如果显示 "Connection refused"，检查iptables：**

```bash
# 在中转服务器上执行

# 1. 检查INPUT链规则
sudo iptables -L INPUT -n --line-numbers

# 2. 检查是否有DROP或REJECT规则
sudo iptables -L INPUT -n | grep -E "DROP|REJECT"

# 3. 检查1025端口规则
sudo iptables -L INPUT -n | grep 1025

# 4. 如果没有1025端口规则，添加规则
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT

# 5. 保存规则
sudo iptables-save > /etc/iptables/rules.v4
# 或
sudo netfilter-persistent save

# 6. 验证规则
sudo iptables -L INPUT -n | grep 1025
```

## ✅ 完整排查脚本

**在中转服务器上执行：**

```bash
#!/bin/bash
echo "=== 连接失败排查 ==="
echo ""

# 1. 检查socat服务
echo "1. socat服务状态："
if systemctl is-active --quiet ssr-relay-socat; then
    echo "  ✅ socat服务运行中"
else
    echo "  ❌ socat服务未运行"
    echo "  启动命令：sudo systemctl start ssr-relay-socat"
fi

# 2. 检查端口监听
echo ""
echo "2. 端口监听："
if netstat -tlnp 2>/dev/null | grep -q ":1025" || ss -tlnp 2>/dev/null | grep -q ":1025"; then
    echo "  ✅ 1025端口正在监听"
    netstat -tlnp 2>/dev/null | grep 1025 || ss -tlnp 2>/dev/null | grep 1025
else
    echo "  ❌ 1025端口未监听"
fi

# 3. 检查SSR客户端
echo ""
echo "3. SSR客户端状态："
if systemctl is-active --quiet ssr-client; then
    echo "  ✅ SSR客户端运行中"
else
    echo "  ❌ SSR客户端未运行"
fi

if netstat -tlnp 2>/dev/null | grep -q ":1080" || ss -tlnp 2>/dev/null | grep -q ":1080"; then
    echo "  ✅ 1080端口正在监听"
else
    echo "  ❌ 1080端口未监听"
fi

# 4. 检查防火墙
echo ""
echo "4. 防火墙状态："
if command -v ufw >/dev/null 2>&1; then
    sudo ufw status | grep 1025 || echo "  ⚠️  1025端口未在防火墙规则中"
elif command -v firewall-cmd >/dev/null 2>&1; then
    sudo firewall-cmd --list-all | grep 1025 || echo "  ⚠️  1025端口未在防火墙规则中"
fi

# 5. 测试本地连接
echo ""
echo "5. 本地连接测试："
IP_RELAY=$(curl -s --max-time 5 --socks5 127.0.0.1:1025 ifconfig.me 2>/dev/null)
if [ -n "$IP_RELAY" ] && [ "$IP_RELAY" != "获取失败" ]; then
    echo "  ✅ 本地连接成功，出口IP: $IP_RELAY"
else
    echo "  ❌ 本地连接失败"
fi

echo ""
echo "=== 排查完成 ==="
```

## 🔧 快速修复

**如果socat服务未运行：**

```bash
# 1. 检查服务文件是否存在
ls -la /etc/systemd/system/ssr-relay-socat.service

# 2. 如果不存在，创建服务文件
sudo nano /etc/systemd/system/ssr-relay-socat.service
# 粘贴服务文件内容（见方案4文档）

# 3. 启动服务
sudo systemctl daemon-reload
sudo systemctl start ssr-relay-socat
sudo systemctl enable ssr-relay-socat
sudo systemctl status ssr-relay-socat
```

**如果端口未监听：**

```bash
# 1. 检查socat是否安装
which socat

# 2. 手动测试socat
socat TCP-LISTEN:1025,fork,reuseaddr TCP:127.0.0.1:1080

# 3. 如果手动测试成功，说明服务配置有问题
# 检查服务文件配置
cat /etc/systemd/system/ssr-relay-socat.service
```

**如果防火墙未开放：**

```bash
# Ubuntu/Debian
sudo ufw allow 1025/tcp
sudo ufw allow 1025/udp
sudo ufw reload

# CentOS/RHEL
sudo firewall-cmd --permanent --add-port=1025/tcp
sudo firewall-cmd --permanent --add-port=1025/udp
sudo firewall-cmd --reload
```
