# 方案4: SSR客户端模式 - 配置指南

## 📋 架构说明

```
本机SSR客户端 → 中转服务器(8.217.122.83:1025)
                → socat转发(0.0.0.0:1025 → 127.0.0.1:1080)
                → SSR客户端(127.0.0.1:1080)
                → 原始SSR服务器(103.248.229.223:8388)
                → 外网（显示原始SSR服务器出口IP）
```

**工作流程：**
1. 本机SSR客户端连接到中转服务器1025端口
2. socat将流量转发到本地SSR客户端（监听1080端口）
3. SSR客户端连接到原始SSR服务器
4. 流量最终通过原始SSR服务器代理

---

## 🚀 安装配置步骤

### 步骤1: 安装SSR客户端（shadowsocksr-libev）

```bash
# 1. 安装编译依赖（Ubuntu/Debian）
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
    build-essential autoconf libtool libssl-dev libpcre3-dev \
    libev-dev libc-ares-dev automake git libmbedtls-dev \
    libsodium-dev pkg-config

# 2. 编译安装
mkdir -p /tmp/ssr-build && cd /tmp/ssr-build
git clone https://github.com/shadowsocksrr/shadowsocksr-libev.git
cd shadowsocksr-libev
git submodule update --init --recursive
./autogen.sh
./configure --prefix=/root/work/shadowsocksr-client --disable-documentation
make -j$(nproc)
make install

# 3. 验证安装
/root/work/shadowsocksr-client/bin/ssr-local --version || \
/root/work/shadowsocksr-client/bin/ss-local --version

# 4. 添加到PATH（可选）
echo 'export PATH=$PATH:/root/work/shadowsocksr-client/bin' >> ~/.bashrc
source ~/.bashrc
```

### 步骤2: 配置SSR客户端

```bash
# 创建配置文件
sudo mkdir -p /opt/shadowsocksr
sudo nano /opt/shadowsocksr/client-config.json
```

**配置文件内容：**

```json
{
    "server": "103.248.229.223",
    "server_port": 8388,
    "local_address": "127.0.0.1",
    "local_port": 1080,
    "password": "原始SSR服务器密码",
    "method": "原始SSR服务器加密方式",
    "protocol": "原始SSR服务器协议",
    "obfs": "原始SSR服务器混淆方式",
    "protocol_param": "",
    "obfs_param": "",
    "timeout": 300,
    "udp_timeout": 60,
    "fast_open": false
}
```

**⚠️ 关键参数：**
- `server`: 必须是 `103.248.229.223`（**不能**使用 `0.0.0.0`）
- `server_port`: 原始SSR服务器端口（如8388）
- `local_address`: `127.0.0.1`（必须）
- `local_port`: `1080`（socat会转发到此端口）

### 步骤3: 启动SSR客户端服务

**方式1: 使用shadowsocksr-libev（推荐）**

```bash
# 创建systemd服务
sudo nano /etc/systemd/system/ssr-client.service
```

**服务文件内容：**

```ini
[Unit]
Description=ShadowsocksR Client
After=network.target

[Service]
Type=simple
User=root
ExecStart=/root/work/shadowsocksr-client/bin/ss-local -c /opt/shadowsocksr/client-config.json
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
# 启动服务
sudo systemctl daemon-reload
sudo systemctl enable ssr-client
sudo systemctl start ssr-client
sudo systemctl status ssr-client

# 验证监听
netstat -tlnp | grep 1080
# 应该看到：tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/ss-local
```

**方式2: 使用Python版本**

```bash
# 创建systemd服务
sudo nano /etc/systemd/system/ssr-client.service
```

**服务文件内容（Python版本）：**

```ini
[Unit]
Description=ShadowsocksR Client (Python)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/shadowsocksr/shadowsocksr/shadowsocks
ExecStart=/usr/bin/python3 local.py -c /opt/shadowsocksr/client-config.json -t 50
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

**注意：** 根据你的实际路径调整 `WorkingDirectory` 和 `ExecStart` 中的路径。

```bash
# 启动服务
sudo systemctl daemon-reload
sudo systemctl enable ssr-client
sudo systemctl start ssr-client
sudo systemctl status ssr-client

# 验证监听
netstat -tlnp | grep 1080
# 应该看到：tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/python
```

### 步骤4: 安装并配置socat转发

```bash
# 1. 安装socat
sudo apt-get install -y socat  # Ubuntu/Debian
# 或
sudo yum install -y socat      # CentOS/RHEL

# 2. 创建socat服务
sudo nano /etc/systemd/system/ssr-relay-socat.service
```

**服务文件内容：**

```ini
[Unit]
Description=SSR Relay Socat (1025 -> 1080)
After=network.target ssr-client.service

[Service]
Type=simple
User=root
ExecStart=/usr/bin/socat TCP-LISTEN:1025,bind=0.0.0.0,fork,reuseaddr TCP:127.0.0.1:1080
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
# 3. 启动socat服务
sudo systemctl daemon-reload
sudo systemctl enable ssr-relay-socat
sudo systemctl start ssr-relay-socat
sudo systemctl status ssr-relay-socat

# 4. 验证端口监听
netstat -tlnp | grep 1025
# 应该看到：tcp  0  0  0.0.0.0:1025  LISTEN  xxxx/socat
```

### 步骤5: 配置防火墙

```bash
# 1. 检查iptables规则
sudo iptables -L INPUT -n | grep 1025

# 2. 如果没有规则，添加iptables规则
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT
sudo iptables-save > /etc/iptables/rules.v4

# 3. ⚠️ 重要：检查并删除iptables NAT表的REDIRECT规则（如果存在）
sudo iptables -t nat -L -n --line-numbers
# 如果看到1025端口被REDIRECT到1080端口，删除这些规则：
sudo iptables -t nat -D PREROUTING -p tcp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D PREROUTING -p udp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p udp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables-save > /etc/iptables/rules.v4

# 4. ⚠️ 重要：配置云服务器安全组规则
# 登录云服务器控制台，添加入站规则：
# - 端口范围: 1025/1025
# - 协议类型: TCP
# - 授权对象: 0.0.0.0/0
```

### 步骤6: 验证配置

**在中转服务器上验证：**

```bash
# 1. 检查服务状态
sudo systemctl status ssr-client
sudo systemctl status ssr-relay-socat

# 2. 检查端口监听
netstat -tlnp | grep -E "1080|1025"
# 应该看到：
# tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/ss-local
# tcp  0  0  0.0.0.0:1025    LISTEN  xxxx/socat

# 3. 测试本地连接
IP_DIRECT=$(curl -s ifconfig.me)
IP_CLIENT=$(curl -s --socks5 127.0.0.1:1080 ifconfig.me)
IP_RELAY=$(curl -s --socks5 127.0.0.1:1025 ifconfig.me)

echo "直接访问IP: $IP_DIRECT"
echo "SSR客户端出口IP: $IP_CLIENT"
echo "转发出口IP: $IP_RELAY"

# 4. 判断结果
if [ "$IP_DIRECT" != "$IP_CLIENT" ] && [ "$IP_CLIENT" = "$IP_RELAY" ]; then
    echo "✅ 配置成功！流量通过原始SSR服务器转发"
else
    echo "❌ 配置失败，请检查"
fi
```

**从本机验证：**

```bash
# 在本机SSR客户端中配置：
# - 服务器地址: 8.217.122.83
# - 端口: 1025
# - 密码、加密方式、协议、混淆: 与原始SSR服务器相同

# 测试连接
curl --socks5 127.0.0.1:1080 ifconfig.me
# 应该返回原始SSR服务器的出口IP（不是中转服务器IP）
```

## 🔍 故障排查

### 问题1: SSR客户端出口IP = 中转服务器IP

**原因：** SSR客户端配置错误，`server`设置为`0.0.0.0`

**解决：**

```bash
# 检查配置
cat /opt/shadowsocksr/client-config.json | grep '"server"'

# 修改为原始SSR服务器IP
sudo nano /opt/shadowsocksr/client-config.json
# 将 "server": "0.0.0.0" 改为 "server": "103.248.229.223"

# 重启服务
sudo systemctl restart ssr-client
```

### 问题2: 外部连接失败、返回RST或Empty reply from server

**原因：** 
1. iptables NAT表的REDIRECT规则与socat冲突（最常见）
2. socat服务未正常运行
3. SSR客户端未正常运行

**解决：**

```bash
# 1. 检查SSR客户端状态（最重要！）
# 如果使用systemd服务：
sudo systemctl status ssr-client
# 如果手动运行，检查进程：
ps aux | grep -E "local.py|ss-local"
netstat -tlnp | grep 1080
# 应该看到：tcp  0  0  127.0.0.1:1080  LISTEN  xxxx/python 或 xxxx/ss-local

# 2. 如果SSR客户端未运行：
# 如果使用systemd服务：
sudo systemctl restart ssr-client
sudo systemctl status ssr-client
# 如果手动运行，启动进程：
cd /opt/shadowsocksr/shadowsocksr/shadowsocks
nohup python3 local.py -c /opt/shadowsocksr/client-config.json -t 50 > /dev/null 2>&1 &
# 或使用screen/tmux保持后台运行

# 3. 检查socat日志中的错误
sudo journalctl -u ssr-relay-socat -n 50 --no-pager
# 如果看到 "Connection refused"，说明SSR客户端无法连接

# 4. 测试SSR客户端是否正常
curl --socks5 127.0.0.1:1080 ifconfig.me
# 应该返回原始SSR服务器的IP

# 5. 如果SSR客户端正常，检查iptables NAT表规则
sudo iptables -t nat -L -n --line-numbers | grep 1025
# 如果看到REDIRECT规则，删除它们：
sudo iptables -t nat -D PREROUTING -p tcp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D PREROUTING -p udp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p udp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables-save > /etc/iptables/rules.v4

# 6. 重启socat服务
sudo systemctl restart ssr-relay-socat
sudo systemctl status ssr-relay-socat

# 7. 检查端口监听
netstat -tlnp | grep 1025
# 应该看到：tcp  0  0  0.0.0.0:1025  LISTEN  xxxx/socat

# 8. 如果返回"Empty reply from server"，按以下步骤排查：

# 8.1 检查SSR客户端进程是否运行
ps aux | grep -E "local.py|ss-local"
netstat -tlnp | grep 1080
# 如果进程不存在，启动SSR客户端

# 8.2 检查socat日志（查看最新错误）
sudo journalctl -u ssr-relay-socat -n 20 --no-pager
# 如果看到 "Connection refused"，说明SSR客户端无法连接

# 8.3 测试SSR客户端是否正常
curl --socks5 127.0.0.1:1080 ifconfig.me
# 应该返回原始SSR服务器的IP

# 8.4 如果SSR客户端正常，重启socat服务
sudo systemctl restart ssr-relay-socat
sudo systemctl status ssr-relay-socat

# 8.5 测试本地socat转发
curl --socks5 127.0.0.1:1025 ifconfig.me
# 应该返回原始SSR服务器的IP

# 8.6 如果本地测试正常但外部连接失败，检查iptables NAT表
sudo iptables -t nat -L -n --line-numbers | grep 1025
# 如果看到REDIRECT规则，删除它们（见步骤5）
```

### 问题3: 外部连接超时或Empty reply from server（本地测试正常）

**原因：** 
1. 云服务器安全组未开放1025端口
2. iptables规则有问题
3. socat无法处理外部连接

**解决：**

```bash
# 1. 检查iptables INPUT规则
sudo iptables -L INPUT -n | grep 1025
# 应该看到ACCEPT规则

# 2. 如果没有规则，添加规则
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT
sudo iptables-save > /etc/iptables/rules.v4

# 3. 检查iptables NAT表（重要！）
sudo iptables -t nat -L -n --line-numbers | grep 1025
# 如果看到REDIRECT规则，删除它们：
sudo iptables -t nat -D PREROUTING -p tcp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D PREROUTING -p udp --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables -t nat -D OUTPUT -p udp -d 127.0.0.1 --dport 1025 -j REDIRECT --to-port 1080
sudo iptables-save > /etc/iptables/rules.v4

# 4. 检查socat服务配置
cat /etc/systemd/system/ssr-relay-socat.service | grep ExecStart
# 应该包含：bind=0.0.0.0

# 5. 检查端口监听
netstat -tlnp | grep 1025
# 应该看到：tcp  0  0  0.0.0.0:1025  LISTEN  xxxx/socat
# 如果是 127.0.0.1:1025，说明socat没有绑定到外部接口

# 6. 如果端口监听在127.0.0.1，更新socat配置
sudo nano /etc/systemd/system/ssr-relay-socat.service
# 确保ExecStart包含：bind=0.0.0.0
sudo systemctl daemon-reload
sudo systemctl restart ssr-relay-socat

# 7. 使用tcpdump监控外部连接
sudo tcpdump -i any -n port 1025 -c 5 -v
# 然后从本机尝试连接，看是否有数据包到达

# 8. ⚠️ 重要：配置云服务器安全组规则
# 登录云服务器控制台，确保安全组允许1025端口入站（TCP）
# - 端口范围: 1025/1025
# - 协议类型: TCP
# - 授权对象: 0.0.0.0/0
```

### 问题4: 删除重复的iptables规则

**如果需要删除重复的iptables规则：**

```bash
# 1. 查看规则编号
sudo iptables -L INPUT -n --line-numbers | grep 1025

# 2. 删除重复的规则（从后往前删除，避免编号变化）
# 假设规则编号是1, 2, 3, 4
sudo iptables -D INPUT 4
sudo iptables -D INPUT 3
sudo iptables -D INPUT 2
sudo iptables -D INPUT 1

# 3. 或者直接删除指定规则（更安全）
sudo iptables -D INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -D INPUT -p udp --dport 1025 -j ACCEPT
sudo iptables -D INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -D INPUT -p udp --dport 1025 -j ACCEPT

# 4. 重新添加一条规则（避免重复）
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT

# 5. 验证规则
sudo iptables -L INPUT -n --line-numbers | grep 1025
# 应该只看到2条规则（TCP和UDP各一条）

# 6. 保存规则
sudo iptables-save > /etc/iptables/rules.v4
```

### 问题5: 删除systemd服务后仍自动重启

**如果删除了服务文件但服务仍自动重启：**

```bash
# 1. 停止并禁用服务（即使文件已删除）
sudo systemctl stop ssr-client
sudo systemctl disable ssr-client

# 2. 重新加载systemd配置
sudo systemctl daemon-reload

# 3. 检查服务状态
sudo systemctl status ssr-client
# 应该显示 "Unit ssr-client.service could not be found" 或类似错误

# 4. 检查是否有残留的进程
ps aux | grep -E "local.py|ss-local"
# 如果还有进程，手动kill
kill <进程ID>

# 5. 检查是否有其他进程管理工具（supervisor、monit等）
ps aux | grep -E "supervisor|monit|systemd"
# 如果有，检查配置并停止相关服务

# 6. 检查是否有定时任务（crontab）
crontab -l
sudo crontab -l
# 如果有相关任务，删除它们

# 7. 检查systemd残留文件
ls -la /etc/systemd/system/ssr-client.service
ls -la /run/systemd/system/ssr-client.service
ls -la /usr/lib/systemd/system/ssr-client.service
# 如果存在，删除它们

# 8. 再次重新加载systemd
sudo systemctl daemon-reload
sudo systemctl reset-failed

# 9. 验证服务已完全停止
sudo systemctl list-units | grep ssr-client
# 应该没有输出
```

### 问题6: 重启iptables服务

**重启iptables相关服务：**

```bash
# 方法1: 如果使用iptables-persistent（Ubuntu/Debian）
sudo systemctl restart netfilter-persistent
# 或
sudo systemctl restart iptables-persistent

# 方法2: 重新加载iptables规则
sudo iptables-restore < /etc/iptables/rules.v4
# 或
sudo netfilter-persistent reload

# 方法3: 如果使用firewalld（CentOS/RHEL 7+）
sudo systemctl restart firewalld

# 方法4: 如果使用iptables服务（CentOS/RHEL 6）
sudo service iptables restart

# 方法5: 手动重新加载规则（通用方法）
# 先保存当前规则
sudo iptables-save > /etc/iptables/rules.v4
# 然后重新加载
sudo iptables-restore < /etc/iptables/rules.v4

# 验证规则已加载
sudo iptables -L -n
sudo iptables -t nat -L -n
```

**注意：** 大多数现代 Linux 系统（Ubuntu 18.04+、Debian 9+）不使用 iptables 服务，而是使用 netfilter-persistent 来保存和恢复规则。

### 问题7: 清空iptables规则

**如果需要清空iptables规则（谨慎操作）：**

```bash
# ⚠️ 警告：清空所有iptables规则可能导致服务器无法访问
# 建议先备份规则

# 1. 备份当前规则
sudo iptables-save > /tmp/iptables-backup-$(date +%Y%m%d-%H%M%S).rules

# 2. 清空所有iptables规则（filter表）
sudo iptables -F
sudo iptables -X
sudo iptables -t nat -F
sudo iptables -t nat -X
sudo iptables -t mangle -F
sudo iptables -t mangle -X

# 3. 设置默认策略为ACCEPT（允许所有流量）
sudo iptables -P INPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
sudo iptables -P OUTPUT ACCEPT
sudo iptables -t nat -P PREROUTING ACCEPT
sudo iptables -t nat -P OUTPUT ACCEPT
sudo iptables -t nat -P POSTROUTING ACCEPT

# 4. 保存规则
sudo iptables-save > /etc/iptables/rules.v4

# 5. 重新添加必要的规则（SSR中转需要的）
sudo iptables -I INPUT -p tcp --dport 1025 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 1025 -j ACCEPT
sudo iptables-save > /etc/iptables/rules.v4

# 6. 重启socat服务
sudo systemctl restart ssr-relay-socat

# 7. 验证
netstat -tlnp | grep 1025
curl --socks5 127.0.0.1:1025 ifconfig.me
```

**如果需要恢复备份的规则：**

```bash
# 恢复备份的规则
sudo iptables-restore < /tmp/iptables-backup-*.rules
sudo iptables-save > /etc/iptables/rules.v4
```

### 问题5: apt-get安装socat失败（MySQL冲突）

**错误：** `ERROR: Unable to start MySQL server`

**解决：**

```bash
# 移除apt包管理器中的MySQL包（不影响源码安装的MySQL）
sudo systemctl stop mysql.service 2>/dev/null
sudo systemctl disable mysql.service 2>/dev/null
sudo apt-get remove --purge mysql-server mysql-server-5.7 mysql-common mysql-client -y
sudo rm -rf /var/lib/mysql/* 2>/dev/null
sudo rm -rf /etc/mysql 2>/dev/null
sudo dpkg --configure -a
sudo apt-get --fix-broken install -y

# 现在可以安装socat了
sudo apt-get install -y socat
```
